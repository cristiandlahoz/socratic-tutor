# Synthetic Data Generation Plan

## Goal

Scale the 3 real parsed dialogues into hundreds of training examples by generating synthetic
Socratic dialogues that preserve the professor's voice, arc, and pedagogical style, covering
a broader range of C programming topics and student error patterns.

---

## Generation Strategy

### Core principle

Each synthetic dialogue must follow the exact same Socratic arc as the real ones:

1. **Real-world analogy** — solve the problem with lápiz y papel before any code
2. **Identify repeated steps** — guide the student to name the pattern
3. **Map steps to constructs** — incrementally translate each step to C via questions
4. **Introduce syntax last** — only after the student has "discovered" the need for it
5. **Validate and correct** — redirect wrong answers without giving the answer directly
6. **Close with an exercise** — assign a related problem for the student to solve alone

### Voice rules

- Preserve informal classroom Spanish: "Nítido!", "Exactoo", "Muy bien", "Profe"
- Short professor turns when asking questions, longer turns when validating + building code
- Student answers are short and realistic — incomplete, sometimes wrong
- Group responses ("Estudiantes:") collapsed to single `user` turn

## Generation Method

### Option A — Manual (current approach)
Write each JSON file directly using the Write tool, one dialogue at a time.

- Pros: full quality control, no hallucination risk
- Cons: slow, does not scale past ~50 dialogues

### Option B — LLM-assisted batch generation (recommended for scale)
Use a carefully crafted meta-prompt that instructs Claude/GPT-4 to generate N dialogues
following the arc rules above, given a seed topic and domain. Then review and save outputs.

**Meta-prompt structure:**

```
You are generating training data for a Socratic programming tutor fine-tune.

Generate a dialogue in Spanish between a professor and a student about [TOPIC] in C,
using [DOMAIN] as the real-world analogy.

Rules:
- Follow this arc: real-world analogy → repeated steps → map to code → introduce syntax → exercise
- Preserve this voice: informal classroom Spanish, short questions, validations like "Nítido!", "Exactoo"
- Include one student error on [ERROR_TYPE] that the professor redirects without giving the answer
- Output in ShareGPT JSON format with roles: system, user, assistant

Topic: [TOPIC]
Domain: [DOMAIN]
Student error: [ERROR_TYPE]
```

### Option C — Programmatic variation
Script that takes a base dialogue and substitutes domain-specific nouns/variables while
preserving the structural arc. Low quality, not recommended for a degree project committee.

---

## Quality Checklist (per dialogue)

Before adding any dialogue to the training set, verify:

- [ ] Starts with a real-world analogy, not code
- [ ] Professor never gives a direct answer without a guiding question first
- [ ] At least one student error with professor redirection
- [ ] Code blocks use ` ```c ``` ` fencing
- [ ] Ends with a new exercise for the student
- [ ] All roles are `system` / `user` / `assistant` — no other values
- [ ] No private notes, meta-commentary or out-of-character text
- [ ] Spanish throughout, informal register preserved
